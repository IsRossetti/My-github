🚀 Git & GitHub

Guia Completo para Controle de Versão e Resolução de Conflitos

GitO que é Git?

Git é um sistema de controle de versão distribuído criado por Linus Torvalds em 2005. Permite que desenvolvedores colaborem em projetos sem precisar estar no mesmo local.

🎯 Principais Vantagens

  • Sistema distribuído (cada clone é um backup completo)
  • Trabalho offline
  • Branches leves e rápidas
  • Histórico completo e imutável
  • Resolução inteligente de conflitos

GHGitHub

GitHub é uma plataforma de hospedagem de repositórios Git fundada em 2008. É a maior comunidade de desenvolvedores do mundo.

🌟 Recursos do GitHub

  • Pull Requests: Revisão de código colaborativa
  • Issues: Rastreamento de bugs e features
  • Actions: CI/CD integrado
  • Pages: Hospedagem gratuita de sites
  • Copilot: IA para programação
💡 Dica: Crie um repositório com seu nome de usuário para ter um README especial no seu perfil!

📋 Comandos Essenciais

Configuração Inicial

git config --global user.name "Seu Nome" git config --global user.email "seu@email.com"

Comandos Básicos

Comando Descrição
git init Inicializa repositório
git clone <url> Clona repositório remoto
git status Estado da árvore de trabalho
git add <arquivo> Adiciona ao staging
git commit -m "msg" Cria commit
git push Envia para remoto
git pull Atualiza do remoto

🌳 Trabalhando com Branches

Comandos de Branch

# Criar e trocar para nova branch git checkout -b feature/nova-funcionalidade # Listar branches git branch # Trocar de branch git checkout main # Deletar branch git branch -d nome-da-branch

🏷️ Convenções de Nomenclatura

  • feature/123-criar-endpoint Nova funcionalidade
  • fix/456-corrigir-bug Correção de bug
  • hotfix/problema-critico Correção urgente
  • docs/atualizar-readme Documentação
  • chore/deps-update Tarefas de manutenção
💡 Boas Práticas:
• Use kebab-case (palavras-separadas-por-hifen)
• Inclua ID do ticket quando possível
• Seja descritivo mas conciso

🔄 Merge e Rebase

Atualizando sua Branch

# Método 1: Merge (cria commit de merge) git checkout feature/minha-branch git fetch origin git merge origin/main # Método 2: Rebase (mantém histórico linear) git fetch origin git rebase origin/main

📊 Estratégias de Merge no GitHub

Estratégia Resultado Quando Usar
Merge Commit Preserva histórico completo Projetos que valorizam rastreabilidade
Squash and Merge Condensa todos commits em 1 PRs com muitos commits pequenos
Rebase and Merge Histórico linear sem merge commit Times experientes

⚡ Git Stash

Guarda mudanças temporariamente sem fazer commit, útil para trocar de branch rapidamente.

# Guardar alterações git stash # Guardar com mensagem git stash save "ajustes no header" # Listar stashes git stash list # Recuperar último stash (mantém no histórico) git stash apply # Recuperar e remover do histórico git stash pop # Limpar todos os stashes git stash clear
🎯 Quando usar: Precisa trocar de branch mas não quer fazer commit das alterações atuais.

🔧 Resolução de Conflitos

🚨 O que são Conflitos?

Conflitos acontecem quando duas pessoas modificam a mesma linha de código. O Git não consegue decidir automaticamente qual versão manter.

🔍 Identificando Conflitos

git merge feature-branch # Saída: CONFLICT (content): Merge conflict in arquivo.js git status # mostra arquivos em conflito

📝 Marcadores de Conflito

<<<<<<< HEAD // Sua versão na branch atual function somar(a, b) { return a + b + 1; // você adicionou + 1 } ======= // Versão que veio da outra branch function somar(a, b) { return (a + b) * 2; // outra pessoa multiplicou por 2 } >>>>>>> feature-branch

✅ Passos para Resolver

1. Identificar arquivos

git status

2. Editar arquivo

Remover marcadores e escolher código correto

3. Adicionar ao stage

git add arquivo.js

4. Finalizar merge

git commit

🛠️ Ferramentas Úteis

# Ver diferenças git diff # Cancelar merge em andamento git merge --abort # Usar ferramenta visual (VS Code, etc) git mergetool
⚠️ Importante: Sempre teste o código após resolver conflitos para garantir que tudo funciona corretamente!

📝 Commits Semânticos

Padronização de mensagens de commit para facilitar leitura do histórico e automações.

🏗️ Formato

<tipo>(<escopo>): <resumo> [corpo opcional explicando o porquê] [Refs: #<issue>]

🏷️ Tipos Principais

feat Nova funcionalidade
fix Correção de bug
docs Documentação
style Formatação
refactor Refatoração
test Testes
build Build/dependências
ci Pipelines CI

✨ Exemplos Práticos

feat(readme): inclusão do campo about me fix(api): tratar null pointer ao criar pedido docs(contrib): adicionar guia de pull request refactor(core): extrair serviço de cálculo de frete chore(deps): atualizar axios para ^1.7.0
🎯 Benefícios: Facilita changelog automático, leitura do histórico e validações de CI/CD.

🚨 Comandos de Emergência

🔙 Voltar a um Commit

Método Quando Usar Comando
git revert Preservar histórico (seguro) git revert <hash>
git reset Reescrever histórico local git reset --hard <hash>
Nova branch Testar sem afetar main git checkout -b fix <hash>

🔍 Investigação

# Ver histórico git log --oneline --graph -10 # Ver quem modificou linha git blame arquivo.js # Procurar no histórico git log --grep="bug fix" # Ver diferenças entre commits git diff commit1..commit2
⚠️ Cuidado: Nunca use git reset --hard depois que commits já foram enviados e usados por outros!

🛡️ --force-with-lease

Mais seguro que --force pois verifica se alguém mais fez push no intervalo:

git fetch origin git rebase origin/main git push --force-with-lease # ✅ Seguro # Em vez de: git push --force # ❌ Perigoso
